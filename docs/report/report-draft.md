# BLE 移動盤點與定位專題報告草稿

狀態：可供共同開發與報告撰寫使用；實機定位、Gazebo、AWS 端到端實驗尚待完成，結果章不得標為最終版。展示／繳交日 2026-12-24。

## 摘要

本專題以 Seeed XIAO ESP32C3 作為固定 Anchor 與待盤點 Target，移動 Raspberry Pi 4B 接收 BLE 廣播。系統先由已知 Anchor 的 RSSI 估計掃描器位置，再累積不同位置的 Target 訊號估計靜止目標位置。觀測來源與定位核心分離，支援實體與 Gazebo 介面，並以網頁呈現盤點、位置、資料品質與回放。Local／WGS84 轉換以場地原點與旋轉角建立對應。雲端規劃以 AWS IoT Core 傳送結果、Cognito 控制觀看權限、GitHub Pages 提供前端，並維持已確認的 0 元現金支出限制。

目前已完成核心與合成資料驗證、網頁／公開回放、六種韌體編譯，以及 RPi 服務與 BLE 掃描啟動；尚不能宣稱已完成實體目標定位或 AWS 實際連線。

## 1. 動機與範圍

應用情境為以移動載具／人攜掃描器盤點分散的 BLE 目標，對牛隻盤點構想先做可控的靜止標籤概念驗證。Target 巡查期間靜止；真實飛行、持續移動目標追蹤與長期耗電量不列首版驗收。

硬體共八個 XIAO，初始四 Anchor、兩 Target、兩備品；RPi 4B 為掃描器。模擬場景、飛控與航線由另一位組員負責，本專題維護觀測契約與共用定位核心。

## 3. 方法與公式

完整符號、推導與程式對照以 [methods.md](methods.md) 為唯一來源：

1. 因果中位數與 EMA。
2. 對數 RSSI 測距與多距離線性校正。
3. 已知高度下的斜距轉水平距離。
4. 第一階段 Anchor 最小平方法與穩健迭代。
5. 第二階段移動觀測定位靜止 Target、窗口與幾何條件。
6. Local 旋轉、ENU／ECEF／WGS84 轉換。
7. 任務去重、可見數與失聯時間規則。
8. 真實位置誤差、MAE／RMSE／P50／P95、成功率與盤點召回率。

報告中明確區分「模型測距殘差」與「對獨立真值的位置誤差」。

## 4. 系統實作與操作

- 共用觀測 schema v1.0 只含 ID、時間、RSSI 及可用的已知高度；真值另外保存。
- RPi 本地頁控制巡查，公開端只讀；每秒發布目前狀態，超過 10 秒未收提示。
- 每個 run_id 保存原始觀測、設定與結果；修改場地設定後以新任務隔離資料。
- 座標設定介面的完成／部署情況須依本次測試紀錄更新；不以本段規劃取代驗證。
- AWS 中斷不影響本地收集，恢復只傳最新狀態，首版完整歷史留在 RPi。
- 韌體提供 ID／角色與訊號參考值；Anchor 座標由 RPi 場地設定管理，不需為改位置重刷 XIAO。

操作與 API 細節見 `docs/runbook.md`、`docs/contracts.md`、`docs/design/site-settings.md`。

## 5. 實驗設計

### 5.1 合成數值與軟體測試

檢驗已知幾何、退化／資料不足、時間順序、資料保存、座標控制點與旋轉往返；合成真值不進求解器。結果見 TEST-002–TEST-005，合成位置誤差表見 methods。

### 5.2 實體步行實驗（待執行）

固定天線高度，量測 Anchor／Target 獨立參考座標，多距離校正；人攜 RPi 沿有轉折路徑巡查。規劃不同擺放／路徑的重複任務，並測 Target 關閉、Anchor 不足與網路中斷。記錄原始資料、設定版本、run_id 與影片。

### 5.3 Gazebo（待組員交付及整合）

記錄世界／飛控版本、航線、三維衰減、廣播時序、噪聲與漏收模型。飛控導航與 BLE 估計分開；觀測與真值分檔，對齊時間後評估。

### 5.4 AWS／網頁端到端（待部署）

核對 Free Plan、裝置授權、受邀使用者唯讀、跨網路顯示及斷線復原。若要報告延遲，必須新增可對齊的產生／發布／接收時間紀錄，不能以「每秒更新」當成已量測的一秒內延遲保證。

## 7. 討論與限制

RSSI 受多徑、遮蔽、天線方向與環境影響；測距模型與濾波存在偏差及延遲。移動觀測須具足夠幾何，單一直線不保證二維解。地理原點與方向誤差會使底圖位置偏移，座標轉換本身不增加 BLE 定位精度。有效解條件會影響誤差樣本，需同時報告成功率。
