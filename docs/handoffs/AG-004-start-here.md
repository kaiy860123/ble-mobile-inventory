# 給 Gazebo 合作組員：先看這份

我們要做的是：在場景放好固定路標與待找物品，讓掃描器走一圈，再在網頁顯示物品的估計位置。

## 名稱先對上

| 名稱 | 白話意思 | 本次數量 |
| --- | --- | --- |
| Anchor | 位置已知的固定路標 | A01–A04，共 4 個 |
| Target | 位置要讓程式估計的物品，巡查期間不移動 | T01、T02，共 2 個 |
| 掃描器 | 沿路接收訊號的角色 | 實機是 RPi，模擬是載具上的虛擬掃描器 |

XIAO 只廣播 ID 與訊號，Anchor 座標記在 RPi 的場地設定。移動 Anchor 後改場地設定即可，無須重刷 XIAO。

## 組員要做什麼

1. 在 Gazebo 建立簡單場景，放 4 個 Anchor 與 2 個 Target。
2. 讓模擬載具走有轉彎的路徑。先做約 60–90 秒資料即可開始整合，這是建議長度，並非保證能定位。
3. 依載具與發訊器距離產生收訊強弱，另加上有記錄參數的噪聲或漏收。
4. 交兩份檔案：收訊紀錄 `observations.jsonl`，以及真正位置的答案檔 `truth.jsonl`。
5. 附上世界場景、航線、設定、程式版本與重新執行方法。

## Codex 會接著做什麼

檢查檔案格式，讓同一套定位程式估計位置，在網頁顯示設備，再用另一份真值檔計算誤差。先交一小段檔案即可開始對接，確認後才接即時傳送。組員不需要先設定 AWS。

## 為什麼要兩份檔案

收訊檔是給程式作答的題目，只放 ID、時間、訊號強弱及已知高度。真值檔是答案，定位完成後才拿來比較。兩者都用公尺、同一個座標原點，且時間要對得上。

## 第一輪成功標準

- 每批資料能送進本地接收服務，回應 `accepted=true`。
- 網頁能列出收到的 T01、T02。
- 收集到足夠有效觀測後，掃描器與 Target 能產生有效位置。
- 保存收訊與結果，能用真值產出誤差表與有效樣本數。

偵測到 Target 不等於已算出位置；算出位置也不等於精度達標，這些要分開檢查。
