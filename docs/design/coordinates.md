# Local／WGS84 與地圖規劃

## 已確認

- 同時保留 Local 與 WGS84 的資料表示。
- 有足夠地理參考資料時，自動轉換座標。
- 有可用 WGS84 位置時，網頁呈現真實地圖底圖。
- Local 仍可在沒有地理參考或沒有網路時獨立使用。
- 使用者已接受 WGS84 原點加旋轉角的設定方式；Local 零旋轉時 X 向東、Y 向北，單位公尺。

## 必要條件

Local 是場域自訂座標；只有 `(x, y)` 數值，不能唯一推得地球上的經緯度。反之，只有某個點的 WGS84，也不足以推得任意場域 Local 的原點與方向。

需要先定義原點、單位、軸向、地理對應、有效範圍與高度處理。候選方式：

1. Local 直接使用東／北方向的公尺座標，設定 WGS84 原點，以局部 ENU 轉換。
2. Local 沿室內牆面／Gazebo 場景軸向，另提供原點與相對正北旋轉角，或足夠的對應控制點求對齊。

已採用「WGS84 原點＋可設定旋轉角」方式，涵蓋上述兩種軸向。PROJ 的 topocentric 轉換需指定原點；實作時明確指定 WGS84 橢球，不依賴工具預設值。

## 旋轉角約定

工程文件統一採用 `rotation_deg`：Local 的 +X 軸相對正東方向的逆時針角度；0° 代表 X 向東、Y 向北，90° 代表 X 向北、Y 向西。角度單位為度。

Local → ENU 平面使用 `E = cos(theta) * x - sin(theta) * y`、`N = sin(theta) * x + cos(theta) * y`；反轉使用反向旋轉。旋轉後再依 WGS84 原點處理地理轉換，保留原始座標與轉換版本。

這是實作所用的明確命名與方向約定，尚未取得實際場地的原點、旋轉角或高度資料。

## 工程資料規則

- Local：`frame_id`、`x_m`、`y_m`，需要時另帶 `z_m`。
- WGS84：具名 `latitude_deg`、`longitude_deg`，高度存在時需標示高度基準，避免經緯度順序混用。
- 轉換設定：`transform_id`、原點、軸向／旋轉、設定來源與有效範圍。
- 已有 Local 與 WGS84 時保留兩者，標示其為原始輸入或轉換衍生值；矛盾不得靜默覆蓋。
- 缺少轉換設定時保留原始座標，顯示「未地理對準」，不產生虛構經緯度。
- 地圖底圖的顯示投影由地圖元件處理，不把底圖投影值誤當 Local 公尺座標或 WGS84 經緯度。
- 地圖失連時退回座標網格，不讓定位流程依賴底圖載入。

缺少地理參考／底圖失敗時使用 Local、資料不足時標示原因與最後有效位置等產品行為已確認。具體欄位名稱與轉換版本屬工程設計，實作後以共用 schema 為準。

座標轉換須獨立執行已知對應點與含旋轉角的往返數值測試；BLE 定位誤差另外量測報告。實體量測先固定天線高度並保存校正資料，高度基準及實際值在場地設定中明確記錄。

## 底圖候選

可評估 Leaflet 等地圖元件搭配 OpenStreetMap 底圖；目前未拍板或實作。若使用 OSM 公共圖磚，顯示來源標示、遵循快取政策，不大量預抓或下載離線圖磚。底圖不會顯示室內房間格局；需要室內平面圖時另加對準後的圖層。
