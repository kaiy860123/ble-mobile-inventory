# RPi、Anchor、Target 現場測試單

日期：2026-11-28。這是測試準備，未勾選的項目不代表已通過。

## 本輪要用的設備

- RPi 4B，一台，開機並接上同一區網。
- 已刷機 XIAO 六塊：A01、A02、A03、A04、T01、T02，各貼相應 ID 標籤。
- 六塊均接穩定 USB 電源。收 BLE 時不必逐塊接電腦 USB，也不需要重刷。
- 捲尺、座標標記、能移動 RPi 的電源或延長線；定位時維持天線高度與方向。

## 0：先連到 RPi

1. RPi 執行 `hostname -I`，以目前 IP 為準。
2. Codex 檢查 SSH 與本地網頁，再讀服務版本、藍牙狀態與日誌。
3. 需要更新時先備份既有設定與原始資料，再部署新版。未確認設定保存前不做破壞性覆寫。

**2026-11-28 實際狀態**：新位址已連入，原主機金鑰相符；保留舊設定及歷史後完成新版部署。六設備同收與座標預覽已驗證，見 [HW-002](../handoffs/HW-002-reception.md)。主機位址只留本地忽略區。

## 1：先做六設備收包，不評精度

1. 六塊通電，暫時放在 RPi 附近，ID 標籤可核對。
2. 本地網頁確認來源是「實機」／`physical`，模式是 `ble`。合成回放不能作本測試證據。
3. 開始新巡查，記錄這一趟 run_id，觀察約 60 秒。
4. 檢查 A01–A04、T01、T02 都有新訊號；Target 已盤點數預期 2。
5. 保存原始 observations、manifest、states 與畫面紀錄。只看畫面快照不能推算封包遺失率。

可用 `python scripts/check-physical-readiness.py --url http://<目前RPi-IP>:8080 --duration 60` 輔助輪詢。它不開新巡查、不改設定、不證明精度，結論只涵蓋本地 API 內看到的新實機觀測。

## 2：量測與設定座標

1. 選場地一角當 Local 原點。沿兩條垂直方向定 X、Y，單位公尺。
2. A01–A04 分布在四周，避免排成一條線。量測各 Anchor X、Y、天線 Z。
3. 填入 `docs/testing/site-measurements-template.csv` 的副本，再透過 RPi 本地場地設定預覽並保存。
4. 沒有真實經緯度與方向資料時先用 Local 網格，不填猜測的 WGS84。
5. Target 的 X、Y 答案另存真值，**不放入定位器的 Target 設定**。已知天線高度可設定。

## 3：RSSI 校正與定位

先按 runbook 的多距離校正方法量測，保留 ID、距離與 RSSI。預設 −59 dBm 不是本場地已完成校正的結果。

定位時保持 T01、T02 靜止，拿 RPi 沿矩形、L 型或其他有轉彎路線移動。先確認掃描器有有效位置，再確認 Target 有足夠移動觀測。單一直線或原地不動可能不足以估出 Target。

每次獨立巡查記錄設定、路徑、高度、run_id、版本、觀測及分離真值。評估 MAE／RMSE 與有效樣本數；尚未對時或沒有真值時，只報功能檢查結果。

## 4：異常測試

| 操作 | 等待與預期 |
| --- | --- |
| T02 斷電 | 超過 10 秒後 T02 顯示暫未收到，目前可見 Target 減少，已盤點數仍保留 2 |
| 只留 2 個 Anchor | 舊 Anchor 觀測逾 3 秒後，掃描器可能無法有效定位，不偽造新位置 |
| 開始新巡查 | 新 run_id，盤點集合重新計算，舊紀錄保留 |
