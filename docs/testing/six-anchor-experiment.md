# 六 Anchor 與原四 Anchor 公平比較實驗指南

日期：2026-11-28。這份文件說明未來新增 `A05`、`A06` 兩個參考點（Anchor）後，如何用白話、可控、可重現的方式，比較「四個 Anchor（A01–A04）」與「六個 Anchor（A01–A06）」的實際差異。

> **目前狀態提醒（重要）**
> - 目前現場只有 **A01–A04** 四個 Anchor 與 **T01、T02** 兩個 Target 完成刷機與量測；**A05 與 A06 尚未刷機、尚未擺放，也尚未量測座標**。
> - 上一輪四點校正產生的候選 RSSI 模型，在完整移動巡查（TEST-037）中導致 `T01` 有效位置由 156 筆驟降至 19 筆，已明確**拒絕並回退**至原本參數（`P1m = -59 dBm`、`n = 2`），**不得復用該候選模型作為正式改善**。
> - 本文件中的所有 `A05`／`A06` 位置建議皆**僅為候選規劃，不是實測座標**；必須等實體擺放並用捲尺實測後，才能寫入場地設定。

## 一、為什麼要做六 Anchor 實驗？

現有四個已量測 Anchor（`room-local` 座標，來自 `HW-003`）：

| 設備 | 目前實測 X（m） | 目前實測 Y（m） | 目前實測高度 Z（m） | 狀態 |
| --- | ---: | ---: | ---: | --- |
| A01 | 0.00 | 0.00 | 0.95 | 已刷機、已量測 |
| A02 | 3.00 | 0.00 | 0.95 | 已刷機、已量測 |
| A03 | 3.00 | 3.80 | 0.78 | 已刷機、已量測 |
| A04 | 1.70 | 3.80 | 0.95 | 已刷機、已量測 |
| **A05（候選）** | **約 0，待實測** | **約 3.8，待實測** | **待實測** | **左上方候選，未刷機、未量測** |
| **A06（候選）** | **約 0，待實測** | **約 1.9，待實測** | **待實測** | **左側中段候選，未刷機、未量測** |

目前 Local 框架沒有 WGS84 原點與旋轉角，「左上方」只指畫面上的低 X、高 Y 區域，不代表地理西北。從現有座標可看出，`X = 0`、較高 Y 的區域缺少參考點；新增位置是待測的補點假設，牆面、遮蔽與實際路徑尚未據此確定最佳解。增加 `A05`、`A06` 的目的，是驗證**在相同場地、相同收訊、相同演算法與參數下**，多兩個分布於不同位置的 Anchor 是否真的能同時改善定位誤差與可用性。

## 二、實驗前準備（實體固定方向與高度）

1. **刷機與貼標籤**：
   - 新增兩塊 XIAO 分別刷入 `A05`、`A06` 韌體並貼上清楚 ID 標籤；通電後先確認 RPi 能同時穩定收到 `A01–A06`、`T01`、`T02` 全部八個 ID。
2. **量測並保存座標**：
   - `A05`、`A06` 放定後，用捲尺量出同一 `room-local` 框架下的 `X`、`Y` 與**天線高度 `Z`**。
   - 原有的 `A01–A04` 位置與 `T01`、`T02` 高度維持不變，方便與前期資料對照。
   - **Target（T01、T02）的 X、Y 真值另存於獨立評估檔，絕不寫進定位器設定**。
3. **固定天線方向與高度**：
   - 所有 Anchor、Target 在整輪實驗期間固定位置與天線朝向，不隨意轉動角度或移動家具。
   - 移動 RPi 時，盡量保持固定高度（與場地設定 `scanner_height_m` 一致）與固定手持／載具朝向，並避免身體直接擋在 RPi 與主要 Anchor 之間。
   - 如果因為實驗設計需要改變 RPi 高度，必須先在設定介面更新並保存 `scanner_height_m`，再開始**新的巡查（新 `run_id`）**，不要在同一趟巡查中混用不同高度。

## 三、核心做法：先六 Anchor 錄製，再用同一份資料做四／六消融比較（Ablation）

為了避免「跑兩次不同時間、走不同路線、環境干擾不同」造成的不公平比較，本實驗採用**同資料消融（ablation）**：

1. **一次錄製完整六 Anchor 資料**：
   - 讓 `A01–A06` 與 `T01`、`T02` 同時通電運作，直接以六 Anchor 設定在 RPi 上錄製完整原始觀測檔 `observations.jsonl`。
2. **離線重播同一份原始資料**：
   - 使用離線比較工具 `scripts/compare-anchor-subsets.py`，建立兩個完全獨立、**冷啟動**的 `InventoryEngine`：
     - **基準組（四 Anchor：`A01,A02,A03,A04`）**：只移除設定檔與觀測批次中的 `A05`、`A06`。
     - **對照組（六 Anchor：`A01,A02,A03,A04,A05,A06`）**：保留完整六個 Anchor。
   - 兩組共用**完全相同**的 Target 觀測、時間戳（`timestamp`）、序號（`sequence`）、來源（`source`）、天線高度、RSSI 模型參數與濾波參數，且都以 `snapshot(now=batch["timestamp"])` 產生逐批結果。
3. **禁止把四 Anchor 資料冒充六 Anchor**：
   - 工具會先校驗完整原始觀測流，並確認 `expanded` 清單中的每個 Anchor（包含 `A05`、`A06`）都存在於場地設定且**實際出現在原始觀測中**；只要缺 `A05` 或 `A06`，工具就會直接拒絕執行。

這是在六設備共同廣播的錄製條件下比較使用四個或六個 Anchor 的求解效果，不能單靠離線移除兩個 ID，就宣稱已量測「只有四設備廣播時」的無線競爭差異。每個 Anchor 曾出現也不代表每一批都新鮮可用，仍依核心 TTL 與品質門檻判斷。

## 四、驗證場景設計（新保留靜態點＋至少三條不同轉折路徑）

不能只看單一靜態點或單一路線就下結論，正式實驗須包含兩類驗證：

### 1. 新保留靜態點（Holdout Static Point）
- 挑選過去未曾使用過的新靜態點位，實測 RPi 的 `X`、`Y` 與高度 `Z` 作為獨立真值，確認全部設備靜止且通電後錄製約 45–60 秒。
- 可同時比較四／六 Anchor 在**靜態 RPi 誤差**與**靜態環境下收訊穩定度**上的差異。
- 注意：靜止時 RPi 估計位置抖動可能仍讓 Target 進入 `valid`（見 `ISSUE-021`），這**不能**當作正式移動定位完成的證據。

### 2. 至少三條不同轉折路徑（Moving Patrols）
- 保持 `T01`、`T02` 靜止，移動 RPi 走過**至少三條不同幾何形狀且包含明顯轉折的路徑**（不要只走單一直線或原地不動），例如：
  1. **路徑 A（外圈矩形／環狀）**：沿場地四周繞行，涵蓋四個角落。
  2. **路徑 B（L 型或 U 型折返）**：涵蓋東西與南北兩個垂直方向。
  3. **路徑 C（S 型或對角折返）**：穿越場地中心與不同象限，改變 RPi 對各 Anchor 與 Target 的相對視角。
- 每條路徑各自開新巡查（獨立 `run_id`），記錄起訖時間、RPi 固定高度、完整 `observations.jsonl`、當下設定檔與獨立真值檔。
- 若移動中沒有獨立量測 RPi 隨時間變化的軌跡真值（例如光學追蹤或定時標記點），真值檔只填固定 Target 的 `X, Y`（`scanner` 留空／`null`），**不報 RPi 移動誤差**。

## 五、正式定位成功率的預先定義規則

如果想報告「正式定位成功率」，必須在**開始錄製之前**先寫下明確規則，包含兩件事：

1. **預定評估時點格點**：例如「確認進入巡查區後的每 1 秒（共 60 個指定評估時點）」或「路線上預先標記好的 10 個檢查點」。
2. **容許新鮮度（Freshness Window）**：在每個預定評估時點 $t_k$，設備必須是 `quality == "valid"`，且其最新解算時間 `position_at` 落在容許新鮮度內（例如 $0 \le t_k - \text{position\_at} \le \Delta t_{\text{fresh}}$），才算該時點成功定位；同一個舊 `position_at` 不能靠重複快照灌水。

**如果沒有事先定義評估時點與容許新鮮度**：
- 正式定位成功率一律標為 `null`（報告寫「未提供」）。
- **絕不事後拿原始觀測批數（例如 176 批）當作分母**來算「有效數 ÷ 原始批數」冒充正式定位成功率。

## 六、怎麼公平看結果？（分開指標、禁止作弊）

比較四 Anchor 與六 Anchor 時，必須**把以下三個維度分開看，缺一不可**：

1. **RPi 掃描器水平誤差（僅限有獨立 scanner 真值時）**：
   - 分別看基準組與對照組各自有效樣本的 `N`、`MAE`、`RMSE`、`P50`、`P95`，以及兩組**共同有效同 `position_at`** 的樣本數 `N` 與各自 `RMSE`。
   - 缺 scanner 真值時，`error_metrics` 為 `null`，不報 RPi 誤差。
2. **Target 水平誤差（T01、T02 分別列出）**：
   - 同樣分開列「各自有效樣本統計」與「共同有效同 `position_at` 的樣本數 `N` 及各自 `RMSE`」。
   - 共同有效樣本能在相同時間配對比較，但仍是兩組都成功的子集合，不能消除對難例失敗的選擇偏差；必須同時看各自有效數及預先定義的成功率，不能只報共同有效 RMSE。
3. **可用性（去重後的有效位置數）**：
   - 按 `position_at` 去重，只計算 `quality == "valid"` 且有新 `position_at` 的次數；快取沿用的舊位置不重複計數。
   - **不能只挑有效解較少、但誤差較低的結果宣布改善**（例如上一輪候選模型 `T01` 有效位置從 156 掉到 19，即使共同樣本 RMSE 下降，整體可用性大幅退化，仍必須判定拒絕）。

### 嚴格禁止的「假改善」做法
- **禁止夾邊界（Clamping）**：不得把超出房間範圍的估計座標硬拉回 `bounds_m` 室內邊界內，再拿來算誤差。
- **禁止放寬品質門檻**：不得為了讓有效位置變多，就放寬 `max_residual_m`（目前範例 2.5 m）、幾何條件數上限、最小樣本數（`target_min_samples`）或最小移動基線（`target_min_baseline_m`）。
- **禁止真值洩漏**：Target 或 RPi 的真實 `X, Y` 只能放進離線評估用的 `--truth` 檔，絕不能進入定位器。

## 七、單一變因原則：參數校正與演算法改動必須另開實驗

- 在四／六 Anchor 消融比較期間，**RSSI 模型參數、濾波設定（`filter_alpha`、`median_window`）與定位演算法必須完全維持固定**（例如統一使用目前回退後的原模型 `P1m = -59 dBm, n = 2`）。
- 如果後續想要：
  - 針對六個 Anchor 重新收集多距離資料做 RSSI 參數校正，或
  - 修改定位求解器、濾波器或權重演算法，
  都必須**另開獨立實驗**並單獨記錄版本、設定與保留集驗證結果，**絕對不要混在同一次四／六 Anchor 比較裡**。否則即使數字變化，也無法分辨是因為多了 `A05`/`A06`，還是因為改了校正參數或演算法。

## 八、取得六 Anchor 實測資料後的離線比較命令（待實測）

等 `A05`、`A06` 刷機、實測座標並錄製真實六 Anchor 原始觀測後，可在本地離線執行（不連網路、不改原始檔）：

```powershell
# 有獨立真值時（例如靜態保留點，或含 Target 真值的移動巡查）
python -X utf8 scripts/compare-anchor-subsets.py `
  <raw_observations.jsonl> `
  <six_anchor_site_config.json> `
  --baseline-anchors A01,A02,A03,A04 `
  --expanded-anchors A01,A02,A03,A04,A05,A06 `
  --truth <separate_truth.jsonl> `
  --max-time-delta-s 0.25 `
  --version <actual_code_commit_sha> `
  --output artifacts/comparisons/six-vs-four-ablation.json

# 尚未整理真值、僅比較各組與共同有效位置數時（省略 --truth）
python -X utf8 scripts/compare-anchor-subsets.py `
  <raw_observations.jsonl> `
  <six_anchor_site_config.json> `
  --output artifacts/comparisons/six-vs-four-availability.json
```

輸出 JSON 會記錄 `schema_version`、原始觀測與設定檔 SHA256、兩組 Anchor ID、輸入批數、`source`、版本、各組去重有效數與誤差指標、共同有效時間點比較及評估限制，且不含任何 `cloud` 憑證、金鑰路徑或主機私密資訊。
